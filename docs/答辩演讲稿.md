# SENTINEL 答辩演讲稿（约 6 分钟）

> 使用说明：方括号里是动作/切换提示，正文可直接照读；语速按 220 字/分钟设计。
> 如果现场只能讲 3 分钟，保留「开场 + 功能演示 + 技术亮点 + 结尾」，其余压缩。

## 0:00–0:40 开场：先讲一个场景

各位评委老师好，我们的作品是 **SENTINEL——一套面向无人小店的双摄边缘 AI 安防系统**。

先讲一个场景：凌晨两点，一间无人便利店，卷帘门外传来脚步声。店里没有人，老板在家里睡觉。

这时候店主其实只关心三件事：**看得见、留得下证据、说得清**。
看得见，是白天的客流和夜里的异常；留得下证据，是出事之后有图、有视频；说得清，是第二天早上有人告诉他“昨晚进来了几个人、停留了多久”。

SENTINEL 就是把这三件事，做在一块 MC632X 双摄板和一个 M5Stack 小智上，而且**不依赖公网、不把画面传到云端**。

## 0:40–1:30 项目概述：一套本地的“哨兵”

系统由两块板组成：MC632X 负责双路视频、AI 推理、事件存证、录像和网页服务；AtomS3R 运行小智，负责语音交互和汇报。

核心能力可以概括成一条闭环：
**双路预览 → 人形检测 / 绊线 / 周界 → 事件图 + 副机位画面 + 5 秒短视频 → 人流量报告 → 小智语音播报。**

这些全部在本地完成：检测在板端 NPU，证据在 SD 卡，网页在板端 8080 端口，不需要云服务，也没有订阅费。

## 1:30–2:30 硬件与软件架构

硬件上，MC632X 是双核 SoC，两路 cv2005 分别接两个 ISP；VPU 同时输出 800×480 MJPEG 给网页预览、512×288 RGB 给 NPU 推理，以及 H.264 给 RTSP。板载 7 寸屏做 OSD 叠加，SD 卡存证据，以太网跑网页和小智接口。

这里有一个真实的硬件约束：**LCD 和 SD0 共用引脚**，所以 SD 只能跑 1-bit；我们把它定在 12.5MHz，优先保证长时间录像的稳定性。

软件上分四层：应用层是网页看板、事件存证、录像报告、AI 联动；服务层是帧缓存、时间同步、LCD 菜单和小智接口；系统层是 RT-Thread 的线程/IPC、DFS + FatFs、lwIP、finsh/msh；最下面是 ISP、VPU、NPU、MMC、LCD 这些驱动和硬件。

## 2:30–4:00 功能演示（配合视频或现场操作）

[切到看板]

左边是双路实时预览：一路是 AI 机位，负责检测和绊线；另一路是副机位，不叠加任何框线。

[点击布防，人员走过绊线]

当有人穿过绊线，事件时间线会立刻出现一条记录。点进去可以看到三样东西：**AI 机位的带框图、副机位的同时刻画面、前后各 5 秒的短视频**。

这里要特别说明：两台摄像头看的是**不同视角**，不是同一张图的“带框/无框版本”。AI 机位负责证明“发生了什么”，副机位负责补充“是谁、穿什么、从哪来”。

[点击 30 秒录制，等待倒计时结束，打开报告]

临时需要记录时，点一下“录制 30 秒”，到点自动停，并生成人流量报告：进入多少人、离开多少人、峰值多少人，都在这份报告里。

[在报告页点“让小智播报”]

最后，点“让小智播报”，小智能用语音把这份报告念出来。这个播报用的是板端预生成的语音片段，不依赖云端 TTS。

## 4:00–5:00 技术难点：三个“硬骨头”

第一，**SD 卡掉卡**。最早录像跑到 20 多秒就停，串口全是 CMD24、CMD17 超时。我们最后定位到三层原因：等卡空闲的超时算错了、超时后控制器停在命令态、以及 25MHz 下信号余量不足。修复之后，默认降到 12.5MHz，连续出错自动再降到 6.25MHz，并且驱动复位后会自动“卸载→重新枚举→重新挂载”。现在长时间录像不需要重启，卡出问题也能几秒自愈。

第二，**双 ISP 曝光耦合**。两路 AE 会互相拉锯，画面一起呼吸式忽明忽暗。我们的做法是 EV 强制同步两路，其它参数按路独立。

第三，**单线程网页的响应**。板端 HTTP 只有一个线程，任何一次慢 IO 都会拖住整页。我们调大了 lwIP 缓冲、关掉 Nagle、把 HTTP 头和 body 合并发送，并让后台标签页暂停轮询。

## 5:00–5:40 结果与创新

现在这套系统可以做到：双路 800×480 预览、三路 RTSP、人形检测与绊线/周界、事件图 + 短视频存证、30 秒快捷录制和定时录制、人流量报告，以及小智语音汇报。

我们的创新点主要是三个：
1. **双机位分工取证**：AI 看行为，副机位看细节；
2. **端侧事件闭环**：检测、存证、报告、播报全部本地完成，不依赖公网；
3. **面向真实硬件的可靠性设计**：把“SD 掉卡必须重启”变成“自动降频、自动重挂”。

## 5:40–6:00 结尾

当然，这套系统还有不足：目前只做人形检测，小智的自由对话仍依赖它的云服务，完全离线时只能做本地播报。后续我们会扩展更多小模型，并把长录像的检索做得更好。

我们想证明的其实很简单：**边缘 AI 不一定非要上云、非要昂贵**。一块双摄开发板加一个语音模块，就能让一间无人小店在深夜里也有人守着，在清晨有人汇报。

谢谢各位评委老师。

## 附：评委可能追问的问题

**Q：断网还能用吗？**
A：板端功能不依赖公网：检测、存证、录像、报告都在本地，网页和 RTSP 走局域网即可。小智的事件/报告播报是本地 OGG 片段，也不需要小智云；但唤醒后的语音对话依赖小智的云服务，完全离线时不可用。

**Q：检测准确率多少？**
A：目前没有做大规模数据集的量化评测，演示场景（室内 2–4 米、正常光照）可以稳定检出并触发事件。我们更关注端侧闭环和证据链的完整性。

**Q：为什么用 MJPEG AVI 而不是 H.264？**
A：MJPEG AVI 用 JS 逐帧解 JPEG 就能在浏览器播放，不依赖 H.264 解码器，跨平台最稳；5fps 对事件取证足够。

**Q：双摄为什么不是同一画面？**
A：两个机位安装位置和朝向不同，是互补视角：AI 机位看行为，副机位看近景/另一角度。时间线里的“原图”就是副机位画面，不是 AI 图的去框版本。

**Q：成本大概多少？**
A：一块 MC632X 双摄板 + 一个 AtomS3R，没有云服务和订阅费；具体 BOM 取决于摄像头和屏幕选型。

**Q：SD 卡还会掉吗？**
A：不能保证 100% 不出错，但我们已经把“出错后必须重启”变成“自动恢复”：默认 12.5MHz、连续出错降频、复位后重新枚举并重挂。
