# SENTINEL 使用说明

本文说明如何把本仓库的源码覆盖到富瀚 FH_RT V3.4.0 SDK 与小智固件中，完成编译、烧录、配置和使用。

> 重要：本仓库只包含**本项目新增/修改的文件**，不包含富瀚 SDK 原始工程，也不包含完整的 xiaozhi-esp32 仓库。
> 所有安装脚本都是“复制 + 备份”，不会删除你现有的文件。

---

## 1. 准备材料

### 1.1 硬件

- 富瀚 MC632X 双摄开发板（DB-XC00 底板，AT070TN94 7 寸 800×480 RGB 屏，2 路 cv2005）
- SD 卡 卡（FAT32，建议 Class10 及以上）
- 网线、5V 电源
- M5Stack AtomS3R + Echo Base（运行小智固件）
- 可选：USB 串口（调试/烧录）

### 1.2 软件

| 软件 | 说明 |
| --- | --- |
| 富瀚 FH_RT V3.4.0 SDK（含 FP11 补丁） | 交叉编译工具链 `arm-fullhanv2-eabi-` |
| Python 3 | SDK 的配置脚本需要 |
| ESP-IDF v6.1 | 编译小智固件 |
| 本仓库源码 | `mc632x/` + `xiaozhi/` |

> SDK 请通过富瀚官方或大赛提供的渠道获取；本仓库不附带。

## 0. 快速测试：直接用预编译固件

只想先跑起来、不想编译时，可以直接烧录仓库 `firmware/` 下的比赛固件：

- `sentinel_20261031_1157_9295ba47.bin`（无头 bin，bootcmd 读 `0x120000`）
- `sentinel_20261031_1157_9295ba47.img`（带头镜像，bootcmd 读 `0x120010`）

md5、bootcmd 判断和烧录命令见 [`firmware/README.md`](../firmware/README.md)。
烧录完成后跳到第 5 节「烧录」之后的「运行」部分即可；小智固件仍需按第 8 节单独编译。

## 2. 安装 MC632X 覆盖层

### 2.1 一键安装（推荐）

```bash
cd sentinel-mc632x/mc632x
./apply_overlay.sh /path/to/FH_RT_V3.4.0_20250123
```

脚本会：

1. 检查目标目录下是否存在 `rt-thread/`；
2. 如果 `app/sentinel` 还不存在，先把 SDK 自带的 `app/media_demo` 复制一份作为底座（跳过 `out/`）——overlay 里只放本项目改动/新增的文件；
3. 把 `overlay/` 里的每个文件复制到 SDK 对应路径；
4. 如果目标文件已存在，先备份为 `*.pre_sentinel`（覆盖层以外的东西不会动）。

### 2.2 手工安装

如果不想用脚本，也可以手工完成同样的两步：

```bash
SDK=/path/to/FH_RT_V3.4.0_20250123
# 1) 以 vendor 的 media_demo 为底座复制一份 sentinel（不含 out/）
mkdir -p "$SDK/rt-thread/app/sentinel"
( cd "$SDK/rt-thread/app/media_demo" && tar cf - --exclude=./out . ) \
    | ( cd "$SDK/rt-thread/app/sentinel" && tar xf - )
# 2) 覆盖本项目文件
cp -a overlay/rt-thread/. "$SDK/rt-thread/"
```

### 2.3 覆盖了哪些文件

`overlay/rt-thread/` 下的文件分为两类：

- **本项目新增的模块**（可直接阅读）：`app/sentinel/sample_demo/stream/*`、`sample_demo/overlay/osd_menu/osd_web_*`、`cam_switch.*`、`rule_layer.*`、`msh_cmds.c` 等；
- **基于 SDK 修改的文件**（建议对照 `*.pre_sentinel` 查看改动）：
  - 应用层：`sample_nna_ivs.c`、`sample_common_stream.c`、`libdmc_http_mjpeg.*`、`jpeg_config.c`（MJPEG chn1/chn2 工作模式）、`nna_config.*`（512×288 模型）、`sample_common_isp.c`（ISP 参数在 ISP 线程落地）、`sample_nna_obj_detect.c`；
  - 驱动/系统：`plat_mmc.c`、`sd.c`（CSD 容量解析）、`board.c`（1-bit / 12.5MHz）、`board_startup.c`（整卡挂载兜底）、`kservice.c` / `rtthread.h`（控制台输出钩子）、`lwipopts.h`、`ffconf.h`；
- **构建系统改动**：`app/Kconfig`、`platform/Kconfig`、`build/rtt_config.mk`、`build/menuconfig.mk`、`configs/*_defconfig`、`local_post_build.sh`——把应用目录从 `media_demo` 改名为 `sentinel`，并让 `make mc632x_defconfig` 默认选中 `SENTINEL`。

## 3. 应用配置

### 3.1 复制参考配置

```bash
cd /path/to/FH_RT_V3.4.0_20250123/rt-thread/app/sentinel
cp /path/to/sentinel-mc632x/mc632x/config/app.config .config
python script/rtt/menu_anno.py .config config.h MC632X
```

> 如果你的硬件/传感器与默认配置不同（比如传感器型号），请不要直接覆盖 `.config`，而是对照第 3.2 节逐项打开需要的选项。

### 3.2 关键配置项

| 配置 | 值 | 作用 |
| --- | --- | --- |
| `CH1_MJPEG_G0` / `CH1_MJPEG_G1` | y | 两路 800×480 MJPEG 预览 |
| `CH1_MJPEG_FRAME_COUNT_G*` | 15 | 预览帧率 |
| `CH2` 编码 | 512×288 RGB888 | NPU 输入 |
| `FH_NN_ENABLE` / IVS | y | 人形检测与绊线/周界 |
| `FH_MJPEG_ENABLE` | 由 MJPEG 配置自动打开 | libmjpeg 推流 |
| `_FS_REENTRANT`（`ffconf.h`） | 1 | FatFs 多线程访问（覆盖层已改） |
| SD 位宽 / 时钟 | 1-bit / 12.5MHz | `board.c` 覆盖层已改 |

> `drivers/mmc/plat_mmc.c`、`drivers/include/fh_mmc.h`、`net/lwip-2.1.2/src/lwipopts.h`、`platform/mc632x/board.c`、`fs/filesystems/elmfat/ffconf.h` 属于 **base OS 库**，修改后必须 `make lib`，只 `make app` 不会重新编译它们。

## 4. 编译

```bash
cd /path/to/FH_RT_V3.4.0_20250123/rt-thread

# 1) SDK 级配置（首次或切换芯片时）
#    覆盖层里的 configs/mc632x_defconfig 就是本项目的完整 .config：

make lib
make app
```

产物：

```text
app/sentinel/out/bin/sentinel.bin      # 无头 bin，烧录用这个
app/sentinel/out/bin/sentinel.elf
```

> 如果 SDK 根目录有 `local_post_build.sh`，可能自动把 bin 复制到 `/srv/tftp/`。

## 5. 烧录

应用分区位于 `0x120000`，大小 `0x300000`。烧哪个文件取决于 u-boot 的 bootcmd：

| bootcmd 读取地址 | 烧录文件 |
| --- | --- |
| `sf read 40000000 0x120000 ...` | 无头 `.bin` |
| `sf read 40000000 0x120010 ...`（厂商默认，跳过 16 字节头） | 带头的 `.img` |

串口进入 u-boot 后先执行 `pri bootcmd` 确认。

### 5.1 tftp + u-boot（推荐）

1. 把 `sentinel.bin`（或 `.img`）放到 TFTP 服务器根目录；
2. 串口进入 u-boot，配置网络后：

```text
tftp 0x40000000 sentinel.bin
sf probe 0
sf erase 0x120000 0x300000
sf write 0x40000000 0x120000 0x300000
reset
```

写入长度用整个应用分区 `0x300000` 即可（也可以按镜像大小向上取整到 64KB，例如 2,744,320 字节 → `0x2A0000`）。

### 5.2 串口 xmodem

使用厂商提供的 RamBoot/xmodem 流程，选择 `xmodem_MC632X_SPI_4_WIRE.img` 引导后烧录；具体见 SDK 的 `烧录步骤.txt`。

### 5.3 串口终端：minicom

u-boot 交互、环境变量设置、烧录命令和启动日志都走串口。Linux 下推荐 minicom。

**安装与权限：**

```bash
sudo apt install minicom
sudo usermod -aG dialout $USER     # 重新登录后生效
ls /dev/ttyUSB* /dev/ttyACM*       # CH340/CP210x 一般是 ttyUSB0，CDC 类是 ttyACM0
```

**连接（115200 8N1，无流控）：**

```bash
minicom -D /dev/ttyUSB0 -b 115200
# 想保存成默认配置：sudo minicom -s → Serial port setup
```

**常用操作：**

- 进入 u-boot：板子上电/复位时连续按 `Enter`；
- 查看环境：`pri`；设置网络：`setenv ipaddr 192.168.70.100`、`setenv serverip 192.168.70.50`、`saveenv`；
- 帮助菜单：`Ctrl-A` 然后 `Z`；清屏：`Ctrl-A` 然后 `C`；
- 退出：`Ctrl-A` 然后 `X`，询问是否复位时选 `Y`（Leave without reset），保留板子现场。

**保存启动日志：**

```bash
minicom -D /dev/ttyUSB0 -b 115200 -C sentinel-boot.log
```

退出后 `sentinel-boot.log` 就是完整串口输出，排查 SD 卡、ISP、网络问题很有用。

**烧录时配合 TFTP：** PC 上先启动 TFTP 服务并把 `sentinel.bin`/`.img` 放进去，u-boot 里 `setenv serverip <PC IP>` 后按 5.1 执行。

**常见问题：**

- `Device /dev/ttyUSB0 is locked`：另一个 minicom/screen 还占着，关掉它，或 `sudo fuser -k /dev/ttyUSB0`；
- 乱码：波特率不是 115200，或硬件/软件流控没关；
- 完全没有输出：确认 TX/RX 没接反、板子确实在上电启动；
- 退出后终端字符异常：执行 `reset` 恢复。

## 6. SD 卡准备

- 格式：FAT32；
- 插卡后上电，系统会自动挂载到 `/mnt`；
- 首次写入时自动创建：

```text
/mnt/snap/left/     左摄（G0）抓拍、无叠加画面、录像
/mnt/snap/right/    右摄（G1/AI）抓拍、事件图、短视频、录像
/mnt/snap/rec_sched.txt
/mnt/snap/reports.log
```

- 卡热插拔后可在网页点「重新挂载」，或等待自动恢复。

## 7. 网络与网页

### 7.1 查看板子 IP

- 串口 msh：`ifconfig`
- 网页接口：`http://<板子IP>:8080/api/sysinfo`

### 7.2 端口

| 端口 | 用途 |
| --- | --- |
| 8080 | 看板与全部 HTTP 接口 |
| 1111 | 左摄 MJPEG 预览 |
| 1112 | 右摄（AI）MJPEG 预览 |
| 1240 / 1246 / 1248 | RTSP（H.264） |

浏览器打开 `http://<板子IP>:8080/` 即可，无需安装客户端。

> 每个 MJPEG 端口同时只支持一个客户端；多个页面同时开会互相顶掉。

### 7.3 小智访问板子（可选）

如果小智在电脑热点网段、板子在有线网段，可用 Windows 端口映射把小智的请求转到板子：

```powershell
netsh interface portproxy add v4tov4 listenaddress=192.168.137.1 listenport=8080 connectaddress=<板子IP> connectport=8080
netsh interface portproxy add v4tov4 listenaddress=192.168.137.1 listenport=1111 connectaddress=<板子IP> connectport=1111
netsh interface portproxy add v4tov4 listenaddress=192.168.137.1 listenport=1112 connectaddress=<板子IP> connectport=1112
```

小智固件里的 `MCB_BASE_URL` 默认就是 `http://192.168.137.1:8080`，这样板子 IP 变了也不用改固件。

## 8. 小智端编译

### 8.1 获取源码

```bash
git clone https://github.com/78/xiaozhi-esp32.git
cd xiaozhi-esp32
```

> 本项目基于 2026-10 的 main 分支的 `atoms3r-echo-base` 板型开发；如果上游结构变化，按第 8.2 节手工合并。

### 8.2 应用覆盖层

```bash
cd sentinel-mc632x/xiaozhi
./apply_overlay.sh /path/to/xiaozhi-esp32
```

脚本会：

1. 把 `overlay/main/boards/m5stack/atoms3r-echo-base/mcb_*.h` 复制到板级目录；
2. 把 `assets/common/*.ogg` 复制到 `main/assets/common/`；
3. 用 `git apply` 应用 `patches/` 下的两处修改（失败时提示手工修改）：
   - `main/CMakeLists.txt`：增加 `esp_http_client` 依赖；
   - `atoms3r_echo_base.cc`：在板级初始化里调用 `mcb::RegisterTools()`。

### 8.3 编译与烧录

```bash
cd /path/to/xiaozhi-esp32
idf.py reconfigure      # 资源是 file(GLOB)，新增 OGG 后必须 reconfigure
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

> 新增语音片段后如果直接 `idf.py build` 报 `_binary_*_ogg_start` 未定义，就是 CMake 缓存了旧的资源列表，执行 `idf.py reconfigure` 即可。

### 8.4 配置

- Wi-Fi：按小智正常配网流程（热点/配网页面）；
- 板子地址：`mcb_client.h` 里的 `MCB_BASE_URL`，默认 `http://192.168.137.1:8080`；
- 如果小智与板子在同一局域网，直接把 `MCB_BASE_URL` 改成 `http://<板子IP>:8080` 即可。

## 9. 功能使用

### 9.1 布防 / 撤防

看板点「布防」后，绊线与周界规则生效；触发时自动存证（AI 机位带框图 + 副机位画面 + 5 秒视频）并语音告警。撤防后仍会做检测，但不产生事件。

> 两台摄像头看的是不同画面：G1 对准监控区域跑 AI，负责“证明发生了什么”；G0 是对准入口/近景（或另一角度）的副机位，画面无叠加，负责补充“是谁、穿什么、从哪来”。时间线里的「原图」就是副机位画面，不是 AI 图的去框版本。

### 9.2 抓拍

看板点「抓拍」：把当前帧存到所选摄像头的目录，并在事件时间线里出现一条“手动”记录。

### 9.3 快捷录制（30 秒）

- 选择左摄/右摄 → 点「● 录制 30 秒」；
- 立即开始，剩余时间逐秒显示，30 秒后自动停止；
- 结束后生成人流量报告，看板出现「查看报告」。

### 9.4 定时录制

- 选择摄像头、日期/时间（或勾选“每天”），点「启用」；
- 到点自动开录，可选录 **右摄 AI** 或 **左摄（无叠加画面）**；
- 设置保存在 `/mnt/snap/rec_sched.txt`，重启后保留。

### 9.5 报告与语音

- 看板「查看报告」或直接访问 `/report?id=N`；
- 报告页点「让小智播报」，小智会轮询到请求并播报进入/离开/峰值人数。

### 9.6 ISP 调参

「图像参数」页可选择「摄像头 1·左摄」或「摄像头 2·右摄」分别调整；EV 会同步两路（防止两个 AE 控制环互相拉锯）。

### 9.7 相册与终端

- 相册按左/右摄显示，可删除、清理、查看容量；
- 网页终端可直接执行 msh 命令（`free`、`df /mnt`、`top` 等），现场排障不用接串口。

### 9.8 msh / 网页终端扩展命令

本项目在 msh 里新增了两个命令，串口和网页终端都能用（`msh_cmds.c`）：

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `cam` | 查看/切换 LCD 画面源 | `cam` 查看当前；`cam 0`/`cam ai` 切到 G1 AI 叠加；`cam 1`/`cam raw` 切到 G0 干净原图 |
| `snap` | 抓拍并存 SD | `snap` 默认抓 AI 叠加；`snap 0`/`snap raw` 抓干净原图 |

`snap` 成功时输出：

```text
snap: ok cam=1 size=38214 seq=12 file=/mnt/snap/right/snap_20261031_120001_00012.jpg
```

失败会明确提示 `no MJPEG frame yet` / `SD not ready` / `write failed`。

常用系统命令：

| 命令 | 说明 |
| --- | --- |
| `help` | 列出当前可用命令 |
| `ps` / `top` | 线程列表 / CPU 占用 |
| `free` | 内存使用 |
| `df /mnt` | SD 卡空间（`df` 必须带路径） |
| `ifconfig` | 网络地址 |
| `ping <ip>` | 连通性测试 |
| `date` | 系统时间 |
| `media_info` | 编码/ISP 运行状态 |
| `vlcview -p <port>` | 启动视频流水线；`vlcview -q` 退出 |

网页终端说明：

- 通过看板「设备终端」或 `/api/term` 调用，命令实际在板端 msh 执行；
- 危险命令（`reboot`、`fal`、`rm`）需要二次确认：先返回 `confirm=1`，再加 `force=1` 执行；
- `cam` / `snap` 内部做了串行化，串口和网页同时操作也安全；录像期间尽量少做 `snap`，避免和写卡抢带宽。

## 10. 常见问题

### 10.1 串口刷 `cmd: 24` / `cmd: 17` 超时

这是 SD 卡写入/读取超时。本版本已经做了：

- 卡空闲等待按 5 秒计时（原代码实际只有约 0.5 秒）；
- 命令响应超时 2 秒，失败后复位控制器；
- 连续出错自动把 SD 时钟从 12.5MHz 降到 6.25MHz；
- 驱动复位后自动“卸载 → 卡重新枚举 → 重新挂载”。

如果仍然频繁出现，优先换一张正牌 Class10 卡，并检查卡座 3.3V 供电。

### 10.2 点「重新挂载」提示失败

- `err=recording`：录像还没停，等几秒再试；
- `err=busy`：有播放器正在读 AVI，关掉播放页再试；
- `err=mount`：卡本身没枚举成功，换卡或重新上电。

### 10.3 事件显示“未保存 / 原图缺失 / 视频缺失”

- 录像期间会主动跳过事件短视频（避免两个 AVI 同时写卡），所以显示“视频缺失”是正常的；
- “原图缺失”指的是副机位画面没保存下来（不是 AI 图的问题）；如果 AI 图也缺失，说明当时 SD 写入失败，本版本会自动恢复并重挂，之后的事件应恢复正常。

### 10.4 事件视频打开 404

说明该事件的短视频文件不存在（当时未保存或被清理）。事件时间线里只有视频存证成功时才会出现「视频」入口。

### 10.5 预览打不开

- 确认 1111/1112 端口没有被防火墙/端口映射挡住；
- 每个端口只支持一个客户端，先关掉其它页面；
- 通过端口映射访问时，1111/1112 也要一起映射。

### 10.6 小智不播报

- 确认小智能访问 `MCB_BASE_URL`（浏览器打开 `/api/status`）；
- 看板报告页点「让小智播报」后，再确认小智已联网、音量正常；
- 检查 `mcb_client.h` 里的地址是否改成了实际网络。

### 10.7 编译相关

- 改了 `plat_mmc.c` / `board.c` / `lwipopts.h` / `ffconf.h` 后必须 `make lib`；
- 传感器参数缺失时执行 `make -C app/sentinel sensor_hex OS=RTT`；
- 切换过 `.config` 后建议 `make -C app/sentinel clean` 再编。

### 10.8 容量显示

8GB 卡显示“共 7.5 GB”是正常的（1024 进制，且 FAT32 有保留区）。看板显示的是“已用 / 剩余 / 共”三项。

### 10.9 断网还能用吗？

分三种情况：

- **没有公网、有局域网**：MC632X 的检测、存证、录像、报告，网页/RTSP，以及小智的事件/报告播报都正常；
- **完全没有网络**：检测、事件存证、录像仍在板端本地运行（布防/定时需要提前设置好），但网页、RTSP、小智都访问不到板子；
- **小智语音**：事件/报告播报是本地 OGG 片段，不需要小智云；唤醒后的语音对话（ASR/LLM/TTS）依赖小智云服务，离线不可用。

## 12. 恢复原状

安装脚本只在目标位置新增/覆盖文件，并保留 `.pre_sentinel` 备份。要恢复某个文件：

```bash
mv <file>.pre_sentinel <file>
```

要整体撤销覆盖层的修改，按 `mc632x/overlay/` 的文件清单逐个还原备份即可。
